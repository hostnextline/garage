# Garage mobile — sources

- `carnet.html` : l'app (même fichier pour claude.ai et pour le site).
- `web/` : version rapide (`build.py` → index.html) et version équipe (`build_team.py` → equipe/ : supa.js = connexion + carnet partagé, equipe.js = rôles, journée, En route, carte, accès ; suivi.html = page du client).
- `supabase/` : base de données (migrations/) et fonctions serveur (functions/en-route, functions/members, functions/vehicle = décodage du VIN par la base gratuite de la NHTSA).
- Téléphone (< 700 px) : version simple automatique (Aujourd'hui, Clients, +, Factures, Plus) ; « Version complète » dans Plus. `web/pwa.json` + `web/icons/` (`mkicons.py`) = icône sur l'écran d'accueil.
- `tests/` : tests navigateur (Playwright, `bash tests/regress.sh` les lance tous) et `tests/stack/` = copie locale de Supabase pour tester
  (Postgres 16 + PostgREST 12.2.3 + Supabase Auth v2.180.0 + Deno, GoHighLevel et itinéraires simulés).
  `node keys.js > keys.json`, appliquer base.sql puis les migrations dans l'ordre (supabase/migrations/), lancer Auth/PostgREST, puis `bash up.sh`.
- Camions = colonnes de l'horaire (`config.trucks`, 3 par défaut dont 2 fermés), équipe du jour dans `days/<date>.crew`, dispos des mécanos dans `avail/<mécano>`.
- Trésorerie : `expenses/<id>` (dépenses) et `receipts/<id>` (photo du reçu, chargée seulement quand on l'ouvre). Rôle « tresorier » dans la base.
- Pour test_tresor / test_team (fichier Excel) : `cd tests && npm i xlsx@0.18.5 --prefix xlsxlib` et une photo `recu_test.jpg` (n'importe quelle grande photo JPEG).
- VIN : scan en direct (BarcodeDetector du téléphone si offert, sinon ZXing 0.21.3 avec notre propre boucle d'images — celle de ZXing inverse une image sur deux et peut rester bloquée), photo ou VIN tapé. Fiche technique par moteur dans `specs/<année-marque-modèle-cylindrée-cyl>` (huile, filtre, etc.), remplie une fois par un mécano ; une autre année du même moteur est proposée « à confirmer ».
- Pour test_vin : `pip install python-barcode`, `cd tests && npm i @zxing/library@0.21.3 --prefix zxinglib`, puis `bash tests/vin/make_videos.sh` (fausse caméra pour Chromium).
- Sauvegardes : fonction `backup` (aucun mot de passe : n'accepte qu'un jeton OIDC signé par GitHub pour le dépôt PRIVÉ hostnextline/garage-sauvegardes, n° 1441054755, branche main) + dossier `sauvegardes/` = contenu de ce dépôt (GitHub Actions chaque nuit, `restaurer.py` pour remettre). Test : `tests/test_backup.py` (faux GitHub local).
- Ordinateur (appareil qui n'est pas un téléphone, fenêtre ≥ 900 px) : menu des sections à gauche, page large (1240 px ; réglages et fiches 900 px). Fenêtre plus petite : barre en bas. Test : `tests/test_pc_layout.py`.
- Hors-ligne (version équipe) : `web/supa.js` garde une copie du carnet dans IndexedDB (`gm-team`) et une file des changements (`outbox`) envoyée au retour du signal ; `web/sw.js` garde la page et ses outils. `?nosw` dans l'adresse désactive le service worker. Test : `tests/test_offline.py`.
- Photos avant/après + signature : `photos/<job>__<n>` (le mécano voit seulement celles de ses jobs). Stock des camions : `stock/<camion>__<article>`. Liste de pièces par moteur dans la fiche technique.
- Page du client : fonction `client` (lien secret dans `client_links`, 120 jours) = voir la facture, la payer par carte (Stripe Checkout ; la clé est enregistrée dans Équipe et accès, ce qui crée l'avis de paiement vers cette fonction), accepter ou refuser des travaux supplémentaires. `web/client.html`. Tests : `tests/test_client.py` (faux Stripe et faux GoHighLevel), `tests/test_parts.py`.
- `tests/regress_team.sh` : tests de la version équipe sur la copie locale de Supabase (`tests/stack/start_all.sh` d'abord). `tests/run_on_day.py` : test_carnet / test_postal supposent un jour de semaine.
- Site en ligne (hostnextline.github.io/garage) : GitHub Pages sert la branche **gh-pages** du dépôt hostnextline/garage. Publier = pousser `main` puis `main:gh-pages` (sinon le site garde l'ancienne version).
- Simplicité (pour débutants) : un seul gros bouton noir par fiche de job (`nextStep` / `nextBtn`, « je » sur le téléphone du mécano, « le mécano » au bureau) ; les actions rares (annuler, client absent, changer l'étape à la main, supprimer) dans « Autres actions » (`#more-fold`). Mots simples : « Client absent » (statut `noshow`), « Facture à finir » / « Terminer la facture » / « Finir plus tard », durée en heures (cases de l'agenda). Bulles « ? » : `HELP` + `help(clé)` (aussi offert à equipe.js via `__garageApi.help`). Guide « Par où commencer » (`guideHTML`, étapes cochées toutes seules ; masqué par `localStorage gm.guide.off`). Réglages : une partie à la fois sur téléphone ET ordinateur, options rares sous « Options avancées » (`advOpen/advClose`). Tests : `window.__allSettings = 1` (script d'init) affiche toutes les parties d'un coup pour les vieux tests ; le découpage est testé par `tests/test_simple.py`, `test_pc_layout.py` et `test_phone.py`.
- Invitations : Équipe et accès → « Inviter une personne » (courriel, rôle). Fonction `members` : `invite` (crée le compte avec un mot de passe que personne ne connaît + un lien secret `#invite=…` valable 7 jours, une seule fois ; seule l'empreinte sha256 est gardée dans `invites`), `invite-resend`, et pour la personne sans compte `invite-info` / `invite-accept` (elle choisit son mot de passe). Le courriel part par GoHighLevel (type Email) si les textos sont branchés ; sinon le propriétaire l'envoie lui-même (bouton courriel / texto déjà écrits). `web/supa.js` : écran « Activer mon compte ». Test : `tests/test_invite.py` (lecture du code QR comme un téléphone : `pip install opencv-python-headless`).
- App sur l'écran d'accueil (version web) : étape du guide + fiche « Mettre l'app sur ton téléphone » (iPhone / Android, code QR sur l'ordinateur, bouton « Installer » quand Chrome le permet), petite carte pour les mécanos, et la fiche s'ouvre toute seule après l'activation d'un compte. « Déjà fait » est gardé dans `data/users/<uid>/app` (automatique quand l'app est ouverte depuis l'icône).
- Voir comme / droits par rôle (nov. 2026) : Équipe et accès → « Voir l'app comme… » (chaque mécano de l'agenda, le trésorier, le bureau ; aussi « 👁 Voir comme X » sur chaque personne). `equipe.js` : `VA` gardé dans sessionStorage `gm.viewas`, `eff()` = le rôle affiché, `me` = le vrai compte (position, textos). Mécano sur un ordinateur : écran de téléphone (`setUi('phone')`, classe `pv-narrow`). `supa.js` : `T.setView()` filtre ce que le mécano recevrait du serveur (ses jobs, les clients et photos de ses jobs, réglages) ; rien n'est effacé. Les boutons de sa journée (position) ne font rien en aperçu ; les autres changements sont enregistrés au nom du propriétaire. « Ce que chaque rôle peut faire » : cases dans `config/roles` (rien de coché = comme avant). Serveur (migration `20261101200000_roles.sql`) : `role_perm()`, trésorier « Modifier les factures » → `can_write_doc` + déclencheur `docs_tresorier_guard` (la facture seulement, statut « terminée » permis, pas de nouvelle job ni d'effacement). Les autres cases = écran seulement. Test : `tests/test_roles.py`.
- Installation revue (oct. 2026) : la fiche reconnaît le navigateur (`browserKind()` : Safari iPhone avec l'étape ••• → Partager d'iOS 26 et « Ouvrir en tant qu'app web », Chrome iPhone, Chrome Android, Samsung Internet) et avertit quand la page est ouverte dans le navigateur d'une autre app (Facebook, Google, courriel…) avec « Copier l'adresse ». Sur l'ordinateur, lien permanent « 📱 Mettre l'app sur ton téléphone » en bas de la barre de gauche. La version d'essai envoie vers la vraie app (`equipe/`) : code QR, bouton « Ouvrir l'app du garage » et lien dans la barre d'essai. Écran de connexion ouvert depuis l'icône : petite phrase « connecte-toi une fois » (l'icône d'iPhone a sa propre mémoire). Nouvelle version publiée : le service worker est revérifié au retour dans l'app et toutes les 30 min ; bandeau « Nouvelle version de l'app prête » + « Mettre à jour ». Tests : `tests/test_install.py` (essai) et la fin de `tests/test_invite.py` (équipe).
- Code QR (fiche « Mettre l'app sur ton téléphone ») : `web/qrcode.min.js` = qrcode-generator 1.4.4 (licence MIT) réduit avec terser, mis DANS la page par build.py / build_team.py (aucun téléchargement extérieur).
- Plusieurs rôles + droits par personne (nov. 2026) : `members.roles` (liste) + `members.perms` (cases changées pour CETTE personne) ; `members.role` reste le rôle principal (propriétaire > bureau > mécano > trésorier), recalculé par le déclencheur `members_a_main_role` (une ancienne mise à jour de `role` seul fait suivre la liste). Migration `20261102120000_plusieurs_roles_droits.sql` : `has_role()`, `my_perm()` (personne → cases du rôle → non), `can_read_doc` / `can_write_doc` / `docs_tresorier_guard` pour plusieurs rôles ; le serveur vérifie « Trésorerie » (dépenses, reçus), « Changer l'horaire du garage et des autres » (days, avail), « Modifier les factures ». Écran : `equipe.js` `RIGHTS` (10 droits : `on` = toujours avec ce rôle, `r` = case offerte, `d` = départ), `gate()`, `permOf()` ; Équipe et accès → rôles en cases + « Ses droits » à l'invitation et dans « Modifier » (Comme son rôle / Ajouté / Enlevé pour cette personne) + tableau « Ce que chaque rôle donne au départ » (`config/roles`). Fonction `members` v6 : `roles`, `perms`. Tests : `tests/test_rights.py`, `tests/test_roles.py`.
- Carte de l'équipe pour tout le monde : fonction `team_map(jour)` (migration `20261102130000_carte_equipe.sql`, case « Voir la carte », oui par défaut) = rendez-vous du jour avec le nom du client, positions pendant la journée, trajets « En route ». `equipe.js` : Centrale fixe (8255 av. Mountain Sights, H4P 2B5 : 45.5005053, -73.6577429), une couleur par mécano, rendez-vous numérotés, trajet du jour Centrale → 1 → 2… par les routes (OSRM public, ligne droite si pas de réponse) avec km et temps, heure d'arrivée d'un trajet en route. Test : `tests/test_map.py` (OSRM simulé).
- Horaire en fenêtre vitrée (`SCH` dans carnet.html) : glisser sur les cases (ordinateur = la semaine dim. → sam., téléphone = un jour), appliquer seulement cette semaine / ce jour, pendant N semaines, ou en permanence ; pour le garage (`config.hours`, `days/<date>` avec `breaks`) et pour un mécano (`avail/<mécano>` : `week`, `dates`). Test : `tests/test_sched.py`.
- Mode vitrine + couleurs de luxe : Réglages → « Couleurs de l'app » (`LUX` : sable, champagne, platine, noir, emeraude, saphir, bordeaux) = `config.lux` pour tout le garage ; `<html data-lux data-theme>` ; l'appareil garde `gm.lux` (petit script au début de la page : pas d'éclair). Sable suit le téléphone (clair/foncé), les autres sont toujours clairs ou toujours foncés. Test : `tests/test_lux.py` (+ la fin de `tests/test_rights.py` pour toute l'équipe).
- Visite guidée (sans points ni jeu) : `TOUR` dans carnet.html (couche sombre, lumière sur la partie expliquée, bulle en verre ; ← → Échap), `tourSteps()` dans equipe.js par parties (`ORDER` selon le rôle principal, chaque partie une fois) ; s'ouvre toute seule la première fois (sauf le propriétaire), « Revoir la visite guidée » dans Plus et en bas du menu sur l'ordinateur, « 👋 Sa première visite » dans Voir comme. Test : `tests/test_tour.py`.
- Tests qui dépendent du jour : `tests/regress.sh` lance test_carnet / test_postal un mercredi et test_dash un mercredi au milieu du mois (`run_on_day.py`).
