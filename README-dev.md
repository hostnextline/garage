# Garage mobile — sources

- `carnet.html` : l'app (même fichier pour claude.ai et pour le site).
- `web/` : version rapide (`build.py` → index.html) et version équipe (`build_team.py` → equipe/ : supa.js = connexion + carnet partagé, equipe.js = rôles, journée, En route, carte, accès ; suivi.html = page du client).
- `supabase/` : base de données (migrations/) et fonctions serveur (functions/en-route, functions/members, functions/vehicle = décodage du VIN par la base gratuite de la NHTSA).
- Téléphone (< 700 px) : version simple automatique (Aujourd'hui, Clients, +, Factures, Plus) ; « Version complète » dans Plus. `web/pwa.json` + `web/icons/` (`mkicons.py`) = icône sur l'écran d'accueil.
- `tests/` : tests navigateur (Playwright, `bash tests/regress.sh` les lance tous) et `tests/stack/` = copie locale de Supabase pour tester
  (Postgres 16 + PostgREST 12.2.3 + Supabase Auth v2.180.0 + Deno, GoHighLevel et itinéraires simulés).
  `node keys.js > keys.json`, appliquer base.sql puis les migrations dans l'ordre (supabase/migrations/), lancer Auth/PostgREST, puis `bash up.sh`.
- Camions = colonnes de l'horaire (`config.trucks`, 3 par défaut dont 2 fermés), équipe du jour dans `days/<date>.crew`, dispos des mécanos dans `avail/<mécano>`.
- Trésorerie : `expenses/<id>` (dépenses) et `receipts/<id>` (photo du reçu, chargée seulement quand on l'ouvre). Rôle « tresorier » dans la base.
- Pour test_tresor / test_team (fichier Excel) : `cd tests && npm i xlsx@0.18.5 --prefix xlsxlib` et une photo `recu_test.jpg` (n'importe quelle grande photo JPEG).
- VIN : scan en direct (BarcodeDetector du téléphone si offert, sinon ZXing 0.21.3 avec notre propre boucle d'images — celle de ZXing inverse une image sur deux et peut rester bloquée), photo ou VIN tapé. Fiche technique par moteur dans `specs/<année-marque-modèle-cylindrée-cyl>` (huile, filtre, etc.), remplie une fois par un mécano ; une autre année du même moteur est proposée « à confirmer ».
- Pour test_vin : `pip install python-barcode`, `cd tests && npm i @zxing/library@0.21.3 --prefix zxinglib`, puis `bash tests/vin/make_videos.sh` (fausse caméra pour Chromium).
- Sauvegardes : fonction `backup` (aucun mot de passe : n'accepte qu'un jeton OIDC signé par GitHub pour le dépôt PRIVÉ hostnextline/garage-sauvegardes, n° 1441054755, branche main) + dossier `sauvegardes/` = contenu de ce dépôt (GitHub Actions chaque nuit, `restaurer.py` pour remettre). Test : `tests/test_backup.py` (faux GitHub local).
- Ordinateur (appareil qui n'est pas un téléphone, fenêtre ≥ 900 px) : menu des sections à gauche, page large (1240 px ; réglages et fiches 900 px). Fenêtre plus petite : barre en bas. Test : `tests/test_pc_layout.py`.
- Hors-ligne (version équipe) : `web/supa.js` garde une copie du carnet dans IndexedDB (`gm-team`) et une file des changements (`outbox`) envoyée au retour du signal ; `web/sw.js` garde la page et ses outils. `?nosw` dans l'adresse désactive le service worker. Test : `tests/test_offline.py`.
- Photos avant/après + signature : `photos/<job>__<n>` (le mécano voit seulement celles de ses jobs). Stock des camions : `stock/<camion>__<article>`. Liste de pièces par moteur dans la fiche technique.
- Page du client : fonction `client` (lien secret dans `client_links`, 120 jours) = voir la facture, la payer par carte (Stripe Checkout ; la clé est enregistrée dans Équipe et accès, ce qui crée l'avis de paiement vers cette fonction), accepter ou refuser des travaux supplémentaires. `web/client.html`. Tests : `tests/test_client.py` (faux Stripe et faux GoHighLevel), `tests/test_parts.py`.
- `tests/regress_team.sh` : tests de la version équipe sur la copie locale de Supabase (`tests/stack/start_all.sh` d'abord). `tests/run_on_day.py` : test_carnet / test_postal supposent un jour de semaine.
- Site en ligne (hostnextline.github.io/garage) : GitHub Pages sert la branche **gh-pages** du dépôt hostnextline/garage. Publier = pousser `main` puis `main:gh-pages` (sinon le site garde l'ancienne version).
- Simplicité (pour débutants) : un seul gros bouton noir par fiche de job (`nextStep` / `nextBtn`, « je » sur le téléphone du mécano, « le mécano » au bureau) ; les actions rares (annuler, client absent, changer l'étape à la main, supprimer) dans « Autres actions » (`#more-fold`). Mots simples : « Client absent » (statut `noshow`), « Facture à finir » / « Terminer la facture » / « Finir plus tard », durée en heures (cases de l'agenda). Bulles « ? » : `HELP` + `help(clé)` (aussi offert à equipe.js via `__garageApi.help`). Guide « Par où commencer » (`guideHTML`, étapes cochées toutes seules ; masqué par `localStorage gm.guide.off`). Réglages : une partie à la fois sur téléphone ET ordinateur, options rares sous « Options avancées » (`advOpen/advClose`). Tests : `window.__allSettings = 1` (script d'init) affiche toutes les parties d'un coup pour les vieux tests ; le découpage est testé par `tests/test_simple.py`, `test_pc_layout.py` et `test_phone.py`.
